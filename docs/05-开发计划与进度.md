# 开发计划与进度管理

任务默认未完成；功能实现并经用户按“用户验证”项实际操作通过后，再勾选对应任务与验证项。

## 一、当前范围

| 维度 | 当前范围 |
|---|---|
| 交付端 | 用户端商城、管理后台、配送员端、Spring Boot 后端 |
| 数据库 | 22 张 P0 表、8 张 P1 表 |
| 核心链路 | 商品浏览 → 购物车 → 下单支付 → 预约配送 → 派单取货 → 送达完成 |
| 核心设计 | 订单状态机、配送状态机、派单算法、运费规则引擎、FEFO 批次出库 |
| 关联文档 | `01-需求分析.md`、`02-数据库设计.md`、`03-系统总体设计.md` |

## 二、阶段总览

- [ ] 阶段 1：工程与账号认证——用户可启动系统并登录三端。
- [ ] 阶段 2：商品浏览与管理——用户可筛选商品，管理员可发布和维护商品。
- [ ] 阶段 3：购物车、下单与支付——用户可完成下单、模拟支付并查看订单状态。
- [ ] 阶段 4：预约配送与调度——用户可预约配送，配送员可接单、取货和送达。
- [ ] 阶段 5：管理端业务闭环——管理员可管理商品、订单、配送、库存与经营数据。
- [ ] 阶段 6：三端体验完善——用户可在桌面端和移动端顺畅完成完整业务流程。
- [ ] 阶段 7：测试与发布——用户可在全新环境启动系统并验收全部核心流程。

### 阶段 2：商品浏览与管理

**阶段目标**

消费者可以浏览、搜索和筛选商品，管理员可以维护商品并立即影响用户端展示。

**任务**

- [ ] 实现商品分类、商品、规格、可选项、图集与库存的数据维护接口。
- [ ] 实现热量、蛋白质、脂肪、碳水、钠、过敏原、储存方式和保质期字段维护。
- [ ] 实现商品图片上传、上下架、排序、推荐与逻辑删除。
- [ ] 实现用户端首页、分类页、搜索、商品列表、商品详情与条件筛选。
- [ ] 实现热量区间、健康标签、价格区间和分类组合筛选。
- [ ] 实现管理端分类管理页面与商品管理页面。
- [ ] 准备可展示的分类、商品、规格、选项与商品图片种子数据。

**用户验证**

- [ ] 用户可按分类浏览、搜索商品并打开详情。
- [ ] 商品详情正确展示图片、价格、规格、营养成分、过敏原、储存方式和保质期。
- [ ] 用户按热量区间或健康标签筛选后，列表结果与条件一致。
- [ ] 管理员新增、修改、上下架商品后，用户端展示同步更新。
- [ ] 已下架商品在用户端显示为不可购买状态。

### 阶段 3：购物车、下单与支付

**阶段目标**

用户可以完成从购物车到模拟支付的完整交易，并在订单详情中看到状态变化。

**任务**

- [ ] 实现购物车新增、删除、数量修改、规格选项修改、勾选和金额合计。
- [ ] 实现结算预览，包括地址、运费、优惠金额、实付金额与整单热量合计。
- [ ] 实现运费规则计算，支持起步价、里程费、夜间附加费和满额免运费。
- [ ] 实现提交订单事务，由服务端重新计价并校验库存、金额和商品状态。
- [ ] 使用乐观锁扣减商品总库存，并按 FEFO 策略扣减批次库存。
- [ ] 实现订单状态迁移表、状态校验、流转日志和状态副作用。
- [ ] 实现模拟支付流水、支付回调与幂等处理。
- [ ] 实现订单列表、订单详情、配送进度时间轴和状态筛选。
- [ ] 实现未支付订单自动取消、库存回补、批次回补和优惠券释放。
- [ ] 实现收货地址新增、修改、删除、默认地址和经纬度记录。

**用户验证**

- [ ] 用户可修改购物车商品数量、规格和选项，金额与热量同步变化。
- [ ] 结算页展示的商品金额、运费、优惠金额、实付金额和整单热量计算正确。
- [ ] 提交订单后生成订单与明细，商品库存和对应批次库存正确扣减。
- [ ] 已下架或库存不足的商品不能加入购物车或提交订单。
- [ ] 模拟支付成功后订单进入待接单状态，订单详情显示支付与状态时间轴。
- [ ] 重复支付回调不会重复改状态，也不会重复扣减库存。
- [ ] 未支付订单超时取消后，库存、批次库存和优惠券恢复正确。

### 阶段 4：预约配送与调度

**阶段目标**

用户可以选择预约时段，系统可以分配配送任务，配送员可以完成取货和送达。

**任务**

- [ ] 实现配送日期与时段的可选查询、容量校验和截止时间校验。
- [ ] 实现预约订单的 `WAIT_SLOT` 状态及到点自动转入待配送。
- [ ] 实现配送单模型、配送状态机、配送轨迹与订单状态联动。
- [ ] 实现候选配送员筛选、距离、负载、评分三因子打分与排序。
- [ ] 持久化派单候选集、各项得分和最终选中结果。
- [ ] 实现系统自动派单、配送员抢单和管理员人工指派三种分配方式。
- [ ] 使用数据库乐观锁保证同一配送单只能被一名配送员抢到。
- [ ] 实现配送员任务大厅、我的任务、取货上报、送达上报和上下线切换。
- [ ] 实现配送轨迹记录与用户端配送进度时间轴联动。

**用户验证**

- [ ] 用户在结算页只能选择可用且未满的配送日期与时段。
- [ ] 预约订单在所选时段开始前显示为待配送时段，到点后自动进入待配送。
- [ ] 系统派单、抢单和人工指派均能把配送单分配给符合条件的配送员。
- [ ] 多名配送员同时抢同一单时只有一人成功。
- [ ] 配送员完成取货和送达后，配送单与订单状态同步更新。
- [ ] 用户可实时看到已分配、已取货、配送中和已送达的进度。
