# 第 2 章 相关技术介绍

本章介绍系统依赖的关键技术：后端框架 Spring Boot 与 MyBatis-Plus、数据存储层 MySQL 与 Redis、前端技术栈 Vue3 以及认证方案 JWT。

## 2.1 Spring Boot 框架

Spring Boot 是基于 Spring 框架的快速开发脚手架，其核心设计目标是“约定优于配置”。开发者只需引入相关依赖，即可获得可运行的 Web 应用，无须手写大量 XML 配置 [15][16]。Spring Boot 的自动配置机制如图 2-1 所示：应用启动时，`@SpringBootApplication` 注解触发组件扫描与自动配置导入；框架读取各依赖 Jar 包中 `META-INF/spring/*.imports` 文件登记的自动配置类清单，逐类评估 `@ConditionalOnClass`、`@ConditionalOnBean`、`@ConditionalOnProperty` 等条件注解，仅当条件满足时才注册对应 Bean；用户通过 `@Configuration` 自定义的 Bean 会覆盖自动配置的默认实现，最终应用上下文就绪并开放服务端口。

![图 2-1 Spring Boot 自动配置流程图](figures/fig-2-1.png)

Starter 是自动配置机制的工程化载体。每个 Starter 是一组预定义依赖与默认配置的集合，例如引入 `spring-boot-starter-web` 即自动装配 MVC、内嵌 Tomcat 与 JSON 序列化能力，引入 `spring-boot-starter-data-redis` 即装配 Redis 连接工厂与模板类。本系统后端基于 Spring Boot 3.5.16 构建，通过 `spring-boot-starter-validation` 完成参数校验，借助其内嵌容器直接运行；同时利用 Spring Boot 的配置绑定机制，将数据库连接、Redis 地址、支付超时时长等运行参数外置到 `application.yml`，由环境变量按需覆盖，满足系统对可移植性的要求。

## 2.2 MyBatis-Plus 持久层

MyBatis-Plus 是 MyBatis 的增强工具，在不修改原有代码的基础上提供了通用 CRUD 能力。其核心组件包括：Mapper 层继承 `BaseMapper<T>` 后自动获得 `insert`、`deleteById`、`updateById`、`selectById` 等单表方法，实体类配合注解即可完成对象与表的映射；条件构造器 `QueryWrapper`/`LambdaQueryWrapper` 支持以链式调用拼装 `where`、`orderBy`、`groupBy` 子句，其中 Lambda 写法通过方法引用引用列名，避免硬编码字段字符串带来的重构风险；分页插件基于拦截器自动改写 SQL 并回查总记录数，业务侧只需构造 `Page` 对象即可获得分页结果；乐观锁支持通过 `@Version` 注解在更新语句中自动追加版本号条件，更新行数为 0 即判定并发冲突。

本系统在单表操作中全面使用 MyBatis-Plus 以减少样板代码，在看板统计、销量排行等涉及多表聚合的场景中编写原生 XML SQL；库存扣减利用其乐观锁支持实现防超卖更新，复杂条件筛选则组合 Wrapper 完成，兼顾了开发效率与查询可控性。

## 2.3 MySQL 与 Redis

MySQL 8.0 是系统的核心关系数据库，承担全部业务数据的持久化。本系统选用 InnoDB 存储引擎，利用其事务与行级锁保障下单、支付等操作的原子性 [17]；借助 ngram 全文解析器建立商品名全文索引，支持中文关键词搜索；使用窗口函数与 CTE 完成近 7 日营业额趋势、销量 Top10 等统计查询；并通过 Flyway 将建表脚本版本化，实现数据库结构的可重复初始化。所有核心表按第三范式设计，同时对订单明细等历史数据做快照冗余，保证商品信息变更不影响历史订单。

Redis 作为高速键值存储，承担三类职责：其一，存储三端登录会话与 JWT 黑名单，实现令牌的主动失效与快速校验；其二，缓存首页分类树、热销商品等低频变更数据，降低数据库访问压力；其三，作为计数器支撑验证码与接口限流等场景。Redis 数据全部允许丢失（会话可重新登录、缓存可回源重建），与 MySQL 中不可丢失的业务数据形成明确的存储分工 [18]。

## 2.4 Vue3 前端框架

本系统三个前端均基于 Vue 3 构建 [19-21]。Vue 3 引入组合式 API（Composition API），以 `setup` 函数组织逻辑，使同一业务功能的代码聚合在一处，显著优于选项式 API 按选项拆分散落的组织方式。工程层面采用 Vite 作为构建工具，开发阶段利用浏览器原生 ES Module 实现秒级启动，生产阶段经 Rollup 打包输出静态资源。

在 UI 层，用户端与配送员端选用 Vant 4 移动端组件库，提供购物车、结算表单、列表卡片等适配 375px 视口的交互组件；管理端选用 Element Plus，提供表格、表单、树形控件等中后台组件，并以 vue-pure-admin 模板作为二次开发基线。全局状态由 Pinia 管理，集中存放登录令牌、用户信息与购物车条目，跨页面共享且便于持久化；路由由 Vue Router 管理，并在导航守卫中完成登录校验与权限拦截；网络层统一封装 Axios，拦截器自动附加 `Authorization` 头并将后端错误码转换为界面提示。

## 2.5 JWT 认证机制

JSON Web Token（JWT）是一种自包含的开放标准令牌，由三段以点号连接的 Base64Url 编码字符串构成：头部（Header）声明令牌类型与签名算法，载荷（Payload）携带用户标识、角色、签发时间与过期时间等声明，签名（Signature）由头部、载荷与服务端密钥经 HMAC SHA256 算法计算得到。客户端登录成功后获得 JWT，后续请求以 `Authorization: Bearer <token>` 头携带，服务端无须查询数据库即可通过重新计算签名验证令牌未被篡改，并依据 `exp` 声明判断是否过期，这使认证过程具备无状态与水平扩展的优势 [22]。

无状态校验无法主动作废尚未到期的令牌，本系统因此引入 Redis 黑名单机制：用户退出登录或账号被禁用时，将该令牌写入黑名单并设置与剩余有效期一致的 TTL；认证过滤器校验签名与有效期后追加检查黑名单，命中的令牌立即拒绝访问，从而在无状态架构下获得了主动登出能力 [23]。系统的三端登录相互独立，Sa-Token 为用户端、配送员端与管理端分别维护登录类型，配合注解式角色校验实现基于角色的访问控制（RBAC），越权请求统一返回 401 或 403 语义化错误 [24]。

## 2.6 本章小结

本章介绍了系统涉及的五项关键技术：Spring Boot 提供自动配置与快速启动能力，MyBatis-Plus 简化持久层开发并支持乐观锁，MySQL 与 Redis 分别承担可靠存储与高速缓存职责，Vue3 技术栈支撑三端一致的开发体验，JWT 与 Redis 黑名单共同构成可主动失效的认证机制。这些技术将在后续章节的系统设计与实现中组合运用。
