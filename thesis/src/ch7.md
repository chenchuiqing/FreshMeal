# 第 7 章 总结与展望

## 7.1 工作总结

本文面向轻食预制菜场景，设计并实现了一套线上订购配送管理系统，完成的工作可归纳为四个方面。

在需求与分析层面，明确了消费者、配送员、商家管理员与超级管理员四类角色的权限边界，按 P0 至 P2 优先级梳理了三端功能需求，建立了订单主流程、订单状态机与配送流程三组业务模型，并从性能、安全、可靠性等六个维度给出非功能需求。

在设计层面，给出了客户端、接入、应用、数据四层架构与六大后端业务模块的划分；设计了包含 31 张数据表的数据库方案，以历史快照、状态留痕与逻辑删除三项原则保障数据质量；以集中式迁移表与副作用钩子实现订单全生命周期的状态机管控；设计了候选集筛选与距离、负载、评分三因子加权的派单算法，对比实验表明其在多付出 0.55km 平均距离的代价下将平均负载率由 39.8% 降至 13.2%；以策略模式实现了起步价、里程费、夜间附加费与满额免运四段式可配置运费规则。

在实现层面，完成了用户端、管理端、配送员端三个前端与 Spring Boot 后端的全部 P0 功能：组合筛选与全文检索、服务端重计价、乐观锁与 FEFO 双层库存、支付幂等回调、预约时段与超时自动推进、抢单并发控制、批次效期管理与经营数据看板；以统一响应、全局异常与注解式 RBAC 收敛横切关注点。

在测试层面，78 项后端测试与 66 项前端测试全部通过，JMeter 三接口压测失败数为 0 且平均响应时间低于 500ms，注入、脚本、越权与金额篡改等安全用例均被有效拦截，全新环境初始化验证通过，系统达到既定验收标准。

## 7.2 不足与展望

系统当前存在三点不足。其一，支付环节采用模拟收银台，未接入真实支付渠道，回调报文、签名校验与退款全链路尚未在真实资金流下验证；其二，配送距离使用 Haversine 直线距离，未考虑实际路网与路况，运费与派单的距离因子只能反映近似关系；其三，派单权重为固定值，未随时段与运力供需动态调整，极端高峰下的调度效果依赖人工指派兜底。

后续工作将沿三个方向展开：接入真实第三方支付，以渠道回调签名校验替代模拟通知，并完善退款与对账闭环；引入地图路径规划服务，以实际道路里程替换直线距离，同步修正运费计费与派单距离因子；基于历史订单与实时运力构建动态调度策略，按时段与区域自适应调整因子权重，并在候选筛选中纳入配送路径顺路度，减少往返取货的空驶里程。此外，优惠券叠加规则、多门店扩展与配送全程定位上报也具备明确的扩展价值，可在现有架构上渐进实现。
