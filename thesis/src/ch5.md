# 第 5 章 系统实现

本章说明系统的工程组织与各端功能的实现方式，展示关键业务逻辑的代码要点，并以实际运行界面呈现主要功能。

## 5.1 工程结构与开发环境

系统采用前后端分离的多工程结构：`server` 为 Spring Boot 后端，`web-shop` 为用户端商城，`web-admin` 为管理后台，`web-rider` 为配送员端，四个工程独立构建、独立部署，通过 RESTful 接口协作。后端基于 JDK 17 与 Spring Boot 3.5.16，使用 Maven 组织依赖；持久层为 MyBatis-Plus 3.5.18，数据库结构由 Flyway 11.7.2 迁移脚本管理；认证使用 Sa-Token 1.46.0，密码哈希使用 Spring Security Crypto 的 BCrypt；接口文档由 SpringDoc OpenAPI 自动生成；定时任务使用 Spring Scheduler 内置调度；测试采用 JUnit 5 与 AssertJ。三个前端均基于 Vue 3.5 与 Vite 8 构建：用户端以 vue-h5-template 为基线并使用 Vant 4 组件库，管理端以 vue-pure-admin 为基线并使用 Element Plus 2.14，配送员端同样使用 Vant 4；全局状态由 Pinia 管理，网络层统一封装 Axios。

## 5.2 公共层实现

统一响应由 `Result<T>` 类封装，固定输出 `code`、`message`、`data`、`timestamp` 四个字段；分页查询返回 `PageResult`，携带记录列表与总条数等分页元信息。业务异常统一继承 `BusinessException` 并携带错误码，`GlobalExceptionHandler` 以 `@RestControllerAdvice` 集中捕获：`BusinessException` 按其携带的错误码返回，参数校验异常 `MethodArgumentNotValidException` 提取首个字段错误返回 400xx，状态冲突类错误码（40900 段）映射为 HTTP 409，认证与权限异常由 Sa-Token 体系映射为 401 与 403，其余未知异常统一记录日志并返回 500xx，保证任何失败路径都输出结构一致的响应体。

认证鉴权基于 Sa-Token 的 JWT 模式实现，`SaTokenConfigure` 为三端分别配置登录类型与路由拦截：`/api/shop/**` 交易接口校验用户登录，`/api/rider/**` 校验配送员角色，`/api/admin/**` 校验管理员角色。`StpInterfaceImpl` 按账号来源返回角色集合，`super_admin` 账号额外获得通配权限，实现注解式 RBAC；`ShopLoginContext` 与 `RiderLoginContext` 为业务层提供当前登录人读取入口。密码存取经 `PasswordEncoderConfig` 提供的 BCrypt 编码器完成，登录校验采用哈希比对，数据库不存明文。

## 5.3 用户端功能实现

**商品浏览与搜索。** 分类树与商品分页接口支持分类、关键词、价格区间、热量区间与健康标签的组合筛选。中文关键词搜索在纯中文且不少于两字时走 MySQL ngram 全文索引，按短语匹配等价实现名称包含查询，其余场景回退 `LIKE`；健康标签以逗号分隔存储，筛选时按标签包含关系组合过滤。商品详情返回主图、规格、营养成分、过敏原与加热方式，规格切换时按规格自身的加价与热量重算展示值。

**购物车与结算。** 购物车条目唯一约束到用户与规格组合，支持增删改与数量调整，金额与整单热量实时合计。商品详情页同时提供立即购买入口，按当前规格与选项直接结算下单，直购行项不写入购物车。结算预览与提交订单复用同一计价服务：服务端重新计算商品金额、按运费规则试算运费、应用优惠后得出实付金额，完全忽略前端提交的金额字段；提交订单在同一事务内创建订单主表与明细、写入商品名与成交价等快照，并调用库存服务扣减总库存。

**库存扣减与回补。** `InventoryServiceImpl` 先以乐观锁更新商品总库存，`UPDATE ... SET stock = stock - ? WHERE id = ? AND stock >= ?` 影响行数为 0 即判定库存不足并回滚；随后按效期升序查询可用批次执行 FEFO 扣减，逐批次扣至需求满足，每笔变动写入库存流水。订单取消时按订单号反查扣减流水，将商品库存与批次库存按原值回补，保证账实一致。

**支付与订单跟踪。** `PaymentServiceImpl` 发起支付时对订单行加悲观锁校验归属与状态，创建待支付流水并写入超时时间；模拟收银台回调处理按 `pay_no` 查询加锁行做幂等判断，重复回调直接返回成功，随后更新流水为成功并经状态机将订单推进至待接单，整个过程位于一个事务内。订单详情页的进度时间轴由状态流转日志与配送轨迹两类记录合并生成，前端按时间倒序渲染节点。

**预约与超时兜底。** 外卖配送下单可选立即配送或预约时段：预约单备餐完成后进入待配送时段状态，`OrderServiceImpl` 以 10 秒间隔的定时任务扫描到点订单并自动激活至待配送，立即配送单则在备餐完成后直接进入待配送并触发派单。另有两个定时任务：每 60 秒取消超过支付时限的待支付订单并回补库存，每 15 秒将备餐完成的订单推进至配送环节，三者共同构成无人值守场景下的状态推进兜底。

**前端协作。** 用户端页面以 Vant 组件搭建，购物车条目由 TanStack Query 统一缓存，写操作成功后在 API 层统一失效缓存，跨页面共享且刷新后从服务端回源；Axios 拦截器为请求自动附加 `Authorization` 头，并将业务错误码转换为 Toast 提示；路由守卫在未登录访问交易页面时重定向至登录页，登录态过期由响应码 40101 触发统一清理。

## 5.4 管理端功能实现

商品管理提供增删改查、上下架与推荐标记，图片上传经 `FileStorageService` 校验扩展名（JPG/PNG/WebP）与大小（不超过 10MB），按日期目录散列存储。订单管理支持多条件分页查询与详情查看，状态干预入口（接单、出餐、取消）同样经状态机流转，非法操作返回 409 状态冲突而不会写库。配送调度页展示待分配配送单，管理员可人工指定配送员，指派逻辑复用派单评分：以被指派者得分为准写入派单日志，`assign_type` 标记为人工指派，保证三种分配通道的日志口径一致。

批次与库存模块实现批次录入、按效期排序的临期预警、报损与盘点，以及库存流水查询；库存流水与订单扣减共用同一张流水表，运营可按订单号追踪完整出入库链路。配送配置模块维护配送区域与运费规则，起步价、每公里单价、夜间附加费与免运门槛均以数据行保存，修改后计费即时生效。数据看板基于原生 SQL 聚合实现：今日营业额与订单数取当日订单实付汇总，趋势图按日分组近 7 日营业额，销量 Top10 联表订单明细与商品表分组统计，区域分布按配送区域聚合配送单量，前端以 ECharts 渲染。

## 5.5 配送员端功能实现

任务大厅查询状态为待分配且未过期的配送单，展示区域、商品量与预计配送费。抢单 `grab` 方法在事务内对配送单行加悲观锁，依次校验未被他人分配、配送员账号启用且在线、服务区域覆盖订单收货区域，随后保存候选评分日志并将配送单置为已分配，同时写入配送轨迹；由于锁的互斥，并发抢单下仅一个请求能完成分配，其余请求得到状态冲突错误。取货与送达上报使用条件更新（`WHERE status = 期望值`），影响行数为 0 即抛出状态已变化提示，防止重复上报与越序操作；订单状态与配送单状态的联动统一由状态机副作用完成。上下线切换修改在线状态字段，直接决定该配送员是否进入派单候选集；业绩统计接口按日汇总单量与收入，与配送单表实时关联，送达完成时按配送单提成累加累计收入。

## 5.7 本章小结

本章说明了四工程分离的工程结构与开发环境，介绍了统一响应、全局异常与 Sa-Token RBAC 三项公共基础的实现；随后按三端展开：用户端实现组合筛选、服务端重计价、FEFO 库存扣减与幂等支付，管理端实现商品与订单管理、人工指派、批次库存与数据看板，配送员端以悲观锁与条件更新保障抢单与履约上报的并发安全，并由三个定时任务提供状态推进兜底；最后以 14 张运行界面截图呈现了各端关键功能的实际效果。
